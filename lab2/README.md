# Лаба 2 — Docker

## Два Dockerfile

| Плохой `Dockerfile.bad` | Хороший `../Dockerfile` |
| --- | --- |
| Плавающий тег `node:22` | Конкретная версия `node:22.23.3-alpine3.24` |
| `COPY . .` до `npm install`: правка любого файла сбрасывает кеш зависимостей | `package*.json` копируются и `npm ci` выполняется до копирования кода |
| Запуск от root | Запуск от пользователя `node` |
| В образ попадают dev-зависимости | В runtime копируются только production-зависимости из отдельной стадии |
| Тяжёлая Debian-основа, нет HEALTHCHECK | Alpine-основа и проверка `/api/ping` |

`.dockerignore` исключает `.git`, `node_modules`, временные файлы и тесты из контекста. Хороший Dockerfile копирует только код сервиса, поэтому фронтенд и учебные материалы не попадают в образ API.

## Проверки

Запустите `bash lab2/measure-builds.sh` для измерения размера и времени пересборки после одной строки кода. Скрипт работает с временной копией последнего коммита и не меняет рабочие файлы. Конкретные значения нужно взять из реального вывода на своей машине.

После `docker compose up -d --build` запустите `bash lab2/check.sh`. Он проверит `whoami`, пересоздаст контейнер MongoDB без удаления тома, подтвердит сохранность записи и покажет, что фронтенд не может соединиться с MongoDB напрямую.
